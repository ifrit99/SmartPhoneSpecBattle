## 0. 前提

- 目標は 60fps。本ガイドの「フレーム」は 60fps の 1 コマ（約 16.7ms）。ms も併記する。
- 1 ログ = 1 ビート（`battle_screen.dart` `_showNextLog`）。ビート長 B は attack 300ms / skill 360ms / defend 300ms。流れは次のとおり。

```
t=0        攻撃側のスプライトが動き出す（lunge / cast / guard）
t=0.4B     当たり。ここで HP・ダメージ数字・ログ行・被弾側の hit・VFX が同時に出る
t=B        攻撃側が idle に戻る
その後     _logDelayMs（800ms / 速度、下限 220ms）だけ待って次のログへ
```

- 演出時間はすべて「/ 再生速度」で縮む。下限は元の 40%（`scaleDurationMs`）。
- 今の長さ（×1）を 1 か所にまとめる。数値の出どころは `battle_sprite.dart` `_durationMs` と `battle_vfx_layer.dart` `_durationMs`。

| 名前 | 何 | 長さ | フレーム |
|---|---|---|---|
| attack（lunge） | 前に 12% 出て戻る。行き 120ms / 戻り 180ms | 300ms | 18f（7f + 11f） |
| cast | 浮いて属性色に染まり、後半で 6% 前進 | 360ms | 22f |
| hit | 白点滅 2 回（60 on / 40 off / 60 on）＋ X ±8px ゆれ | 300ms | 18f |
| guard / heal | 後退＋盾の楕円 / 緑ティント | 300 / 500ms | 18 / 30f |
| victory / defeat | 2 回ホップ / 沈んで薄くなる | 400 / 600ms | 24 / 36f |
| flash | 画面全面を属性色 0.35 → 0（crit は白 0.50） | 160ms | 10f |
| slash | 中心を通る線 2 本（crit 3 本）。白 3px の芯＋属性色 5px | 180ms | 11f |
| burst | 3〜4px の正方形粒 8〜12 個が放射 | 320ms | 19f |
| ring | 円環 0.3 → 0.8 charSize | 300ms | 18f |
| sparkle | 2px の粒 6 個が足元から上へ | 500ms | 30f |
| DamagePopup | 数字。跳ねて上昇、最後の 30% でフェード | 800ms | 48f |
| SkillNameBanner | スキル名の帯。fade in 80 / hold 400 / out 120 | 600ms | 36f |

## 1. タイミング

### 1-1. 三つの区切り：溜め・当たり・余韻

演出は「これから起きる」「起きた」「あとが残る」の 3 つに分けて考える。どれかが欠けると、絵を貼って消しただけ（シール）に見える。
(参考: effekseer-vfx-skill references/timing.md, craft.md)

| 区切り | 問い | 目安（×1） | 今の SSB |
|---|---|---|---|
| 溜め | どこで・いつ起きるか分かるか | 通常攻撃 4〜8f（67〜133ms）。スキルはもう少し長く 8〜14f | lunge 行き 7f、cast の浮き 9f。足りている |
| 当たり | その瞬間が前後より明らかに強いか | **2〜5f（33〜83ms）**。一番明るく、一番大きく、そして短く | hit の白点滅 1 回目 60ms ≒ 4f は良い。slash は線が伸び切る前に薄くなるので、一番明るい瞬間と一番大きい瞬間がずれている（→ §4 候補 1） |
| 余韻 | 消えるまで動き続けているか。時間どおりに消えるか | 全体の半分以上を余韻に使う。最後まで「動いて」消える（等速で薄くなるだけにしない） | burst 19f・sparkle 30f。長さは良いが、粒が等速で alpha も直線（→ §4 候補 2） |

守ること:
- **当たりで出すものは全部同じフレーム**に出す。HP 減少・数字・ログ行・白点滅・slash/burst。今の実装は `_showNextLog` の 0.4B で揃っている。ここをずらさない。
- 当たりの白（全面フラッシュ・白点滅）は短く。10f を超えて白いままだと「光っている」ではなく「白く塗りつぶされた」に見える。
- 回復・防御・自己バフは当たりを持たない。ゆっくり出て、上に動き、少しだけ行き過ぎて戻る。白フラッシュは付けない。
- クリティカルは「当たりを強くする」のであって「長くする」のではない。白の量と線の本数を増やし、長さは同じかヒットストップ分だけ延ばす。

### 1-2. 3頭身ドットでの画面ゆれとヒットストップ

スプライトは 48px 等倍（表示は 50〜100 論理 px）。体が小さいので、動かす量は少しでよく、止める方が効く。

**ヒットストップ（当たりの瞬間に止める）**
- 当たりのフレームで攻撃側を**頂点のまま 2〜4f（33〜67ms）止める**。被弾側は白点滅の 1 回目がちょうど重なる。これだけで「刺さった」感じが出る。
- クリティカルは 5〜8f（83〜133ms）。これ以上はテンポが落ちる。
- 速度 ×3 のときは 1f 以下になるので、効いていなくてよい（下限 40% で自然に消える）。
- 今の実装にはヒットストップがない。lunge は頂点に着いた次のフレームから戻り始める（→ §4 候補 3）。

**画面ゆれ（フィールド全体を揺らす）**
- 通常攻撃では揺らさない。被弾側の X ±8px ゆれで足りる。ログや HP バーまで揺れると読めなくなる。
- 揺らすならクリティカルと決着だけ。**2〜4px、4〜6f、減衰つき**。揺らすのは `_buildBattleField` の中身だけで、ログ・ボタン・TURN バッジは揺らさない。
- 減モーション（`MediaQuery.disableAnimations`）のときは 0。
- これは今の実装にない。入れるかはユーザー判断（RFC §9-1）。本ガイドでは「入れるならこの量」だけ決めておく。

### 1-3. 速度 ×1〜×3、スキップ、減モーション

- すべての長さは `/ 速度`、下限 40%。×3 で attack は 120ms（7f）。当たりの 2〜5f は ×3 でも 1〜2f は残る。
- 「余韻」は ×3 で短くなってよいが、**残留してはいけない**。次のログの当たりに前の粒が重なると濁る。
- スキップは全部止めて勝敗ステートだけ出す（`_skipToEnd`）。粒・帯・数字が残っていたら不合格。
- 減モーションでは動き・粒・ティントをすべて 0 にし、HP・数字・ログの**タイミングは変えない**（RFC §4-3）。

## 2. 重ね方（層の役割）

### 2-1. 画面の層

`battle_screen.dart` の Stack の順。下から。

| 層 | 実装 | 役割 | 守ること |
|---|---|---|---|
| 背景 | `battle_bg.png`（cover・上寄せ） | 舞台。下 2/3 が暗い | 触らない。暗部にスプライトを置く前提を崩さない |
| スプライト | `BattleSprite` ×2（`RepaintBoundary`） | 主役。動き・ティントはここだけ | 常時のグロー・オーラ・台座なし。ティントは 360ms 以内 |
| HUD | 名前・HP バー・TURN | 情報 | 演出で隠さない・揺らさない |
| VFX | `BattleVfxLayer`（`CustomPaint` 1 枚・Ticker 1 本） | 芯・本体・粒・全面フラッシュ | 層は 1 枚のまま。VFX ごとに Widget を増やさない |
| 数字 | `DamagePopup`（`Positioned` を積む） | 結果 | 一番上。VFX に隠されない |
| 帯 | `SkillNameBanner`（TURN の下） | スキル名 | スプライトと重ねない。フィールドの外側（上端）だけ |

### 2-2. 色の役割（1 つの VFX の中で）

「小さく一番明るい芯」「形を持つ本体」「あとに残る粒」の 3 つが見えれば足りる。層の数は品質ではない。
(参考: effekseer-vfx-skill references/layering.md)

| 役割 | SSB では | 目安 |
|---|---|---|
| 芯 | 白。slash の 3px 線、burst の中心 1〜2 粒、hit の白点滅 | 本体の 0.2〜0.5 の幅。当たりで見えて、消えたあとも本体が残る |
| 本体 | 属性色（`elementColor`）。slash の 5px 外縁、burst の粒、ring、cast のティント | 白が消えたあとも形が読めること。消すときは alpha を落とす前に色を少し暗くする |
| 粒 | 本体より小さく、本体より長く残る。sparkle、burst の遅い粒 | 彩度を少し落とす。最後まで動く |
| 全面フラッシュ | `flash`。属性色 0.35、crit は白 0.50 | **同時に 1 枚だけ**。10f 以内で 0 に戻る。帯・数字の上に乗ってよいが、スプライトを 2 回以上白く塗らない |
| 暗い縁 | 原則なし | 背景が暗いので黒い縁取りは要らない。背景上 1/3 の明るい空にかかる粒だけ、白ではなく属性色を使う |

守ること:
- 色はまず**白黒で見る**。芯・本体・背景が全部白に近いなら、粒を足しても構造は戻らない。先に「どれが白くしているか」（フラッシュ、点滅、slash の芯）を 1 つずつ外して見つける。
- 属性ごとに色は変えるが、形は変えない（RFC v1）。形の差は後続（RFC §9-3）。
- 白くなりすぎたら直す順番: 全面フラッシュを弱く → 当たりを短く → 本体の白い時間を削る → 最後に暗い色を足す。一度に全部いじらない。

## 3. ドット絵での作り方のコツ

スプライトは 48×48 等倍・1px の暗い輪郭・ディザなし・AA なし（`docs/rfc_character_art.md` §2-6）。VFX もそれに合わせる。

**色数**
- 1 つの VFX で使う色は **白＋属性色＋属性色の暗め 1 色** の 3 色まで。グラデーションは使わない。
- ティントは `ColorFiltered`（srcATop）でスプライト全体を染める。パレットを一瞬差し替える SFC のやり方そのもの。これで十分。
- 消すときは alpha より先に「色を暗くする」。白→属性色→暗い属性色→消える、の順で見える。

**解像度（粒の大きさと位置）**
- 粒は **2 / 3 / 4px の正方形**だけ。奇数の斜め線や円は AA なしでギザギザになるが、それが時代感なのでよい。
- 座標は**整数に丸める**（`.roundToDouble()`）。スプライトの変位は丸めている（`battle_sprite.dart`）。粒も揃える。
- 大きさは charSize 比で決め、360×640 と 430×932 で同じ比率になるようにする（RFC §2-2）。
- ぼかし（`blurRadius`）・影・半透明の重ね塗りは Web で重く、ドット絵にも合わない。VFX 層では使わない。

**輪郭と形**
- スプライトの 1px 輪郭を演出で壊さない。回転・非整数倍の拡縮はしない（格子が崩れる）。許すのは移動・整数倍・ティント・不透明度。
- 線（slash）は「白の芯＋属性色の外縁」で輪郭を作る。今の 3px/5px の組はこれになっている。
- ring は線幅 2px 固定。半径が伸びても太らせない。

**動き**
- 粒は**速く出て、ゆっくり止まり、少し落ちる**。等速の直線は「飾りのノイズ」に見える。(参考: craft.md「シールに見える 5 つの理由」)
- 方向を持たせる。攻撃は相手側へ、回復は上へ、防御は手前へ。全方向に均等はクリティカルの burst だけでよい。
- 3頭身なので移動量は小さく。lunge 12%（48px で約 6px）、ボブ ±1px はこのままでよい。被弾ゆれの ±8px は体の 1/6 で大きめ。気になったら ±4〜6px に落とす（§5）。

## 4. 今の実装でまず直すと良い候補（3 つまで）

どれも grok-4.6 が小さい PR 1 本で出せる大きさ。1 PR で 1 候補。順番はこのとおりでなくてよい。
共通の完了条件: `flutter analyze` 0 / `flutter test` 全パス / `pubspec.yaml`・`assets/`・`lib/domain/**` に差分なし / ×1 と ×3 で 1 バトル通してブラウザ確認 / スキップで残留なし。

### 候補 1: slash を「当たった瞬間が一番強い」形にする

- 対象: `lib/presentation/widgets/battle/battle_vfx_layer.dart` `_paintSlash`、テスト `test/presentation/battle/battle_vfx_layer_test.dart`
- 今: 線の長さが 0 → 1.2 charSize に 180ms かけて伸び、alpha は最初から `1 - t` で落ちる。線が伸び切ったときにはもう薄い。一番明るい瞬間（t=0）には線がない。
- 変える: 最初の 2f（t < 0.2）で全長まで伸ばし、alpha 1 のまま約 5f（t ≒ 0.45 まで）保ち、残りでフェード。合計 180ms は変えない。白 3px の芯と属性色 5px の外縁も変えない。
- 進め方: 長さと alpha の計算を `slashLength(t)` / `slashAlpha(t)` のような小さな純関数に出し、それをテストする（`paint` 自体はテストしない）。
- 完了条件: t=0.3 で長さが最大・alpha 1、t=1 で alpha 0 がテストで確認できる。ブラウザで、数字が出た瞬間に白い X がはっきり見え、×3 でも次のログに線が残らない。

### 候補 2: 粒に緩急をつける（burst / sparkle）

- 対象: `lib/presentation/widgets/battle/battle_vfx_layer.dart` `_paintBurst`・`_paintSparkle`、テスト同上
- 今: burst の距離は `0.6 × charSize × t`（等速）、alpha は `1 - t`（直線）。sparkle も等速で上昇し直線で消える。粒の座標は整数に丸めていない。
- 変える: 距離に `Curves.easeOutCubic` をかけて「速く出てゆっくり止まる」。burst は `t²` に比例する小さな落下（0.1〜0.15 charSize）を足す。alpha は t=0.6 まで 1、その後フェード。座標を `.roundToDouble()`、粒の大きさを 2/3/4px に揃える。長さ（320 / 500ms）は変えない。
- 進め方: 距離・落下・alpha を純関数に出してテスト。
- 完了条件: t=0.5 で距離が最大の 70% 以上（速く出る）、t=1 で最大、落下量が単調増加、がテストで確認できる。ブラウザで、粒が止まりながら消えて見える。スキップで粒が残らない。

### 候補 3: 通常攻撃にヒットストップ（頂点で 3f 止める）

- 対象: `lib/presentation/widgets/battle/battle_sprite.dart` `_lungeProgress`、テスト `test/presentation/battle/battle_sprite_test.dart`
- 今: 行き 0〜0.4（120ms）、戻り 0.4〜1.0（180ms）。頂点に着いた次のフレームから戻り始める。
- 変える: 行き 0〜0.4（120ms）、**止め 0.4〜0.57（約 50ms = 3f）**、戻り 0.57〜1.0（約 130ms）。合計 300ms は変えないので、`battle_screen.dart` の 0.4B（当たり）はそのまま同期し、画面側の変更は要らない。×3 では止めが約 1f になり、自然に効かなくなる。
- 仮定: `_castPose` の後半 lunge も同じ関数を通るので、スキルの小さな前進にも止めが入る。まずはそれでよい。気になれば attack だけに限定する。
- 完了条件: 既存テスト「120ms で +x、300ms で 0・idle」が無変更で通る。新テストで 140ms と 165ms の X 変位が 120ms と同じ（止まっている）、200ms では小さくなっている。ブラウザで、×1 のとき攻撃側が当たりで一瞬「刺さって」から戻る。

## 5. 後で見るもの（候補に入れなかったもの）

- crit の白フラッシュ 0.50 が 180ms（11f）直線フェード。「白いまま」が長い。候補 1・2 のあと、`flash` を 4f で 0 に落とす形に変える。
- 被弾ゆれ ±8px は 3頭身には大きめ。±4〜6px に下げるか、クリティカルだけ ±8 にする。
- クリティカル・決着時の画面ゆれ（§1-2）。入れるかはユーザー判断（RFC §9-1）。
- 属性ごとの形（炎は上昇、水は波紋 …）。RFC §9-3 の v2。
- actor 判定の名前一致（RFC §9-2）。演出ではなく判定の話なので別タスク。
